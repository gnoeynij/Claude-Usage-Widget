# v2.5.3 — Fable 5.1 cost accuracy

Anthropic shipped Claude Fable 5.1 on September 1. Its cache reads cost a quarter of what Fable 5's did, and the widget kept charging the old rate — cache reads are by far the largest token bucket in a typical Claude Code session, so the error went straight into your displayed total with nothing looking wrong on screen.

## Fixed

- **Claude Fable 5.1 and Claude Mythos 5.1 cache reads were priced 4× too high.** Both launched on September 1 with the same $10/$50 input/output and the same cache-write rates as Fable 5, but their cache reads bill at 0.025× the base input price ($0.25 per MTok) instead of the 0.1× ($1) that every other Claude model uses — the first time that multiplier has differed by model. The widget had no entry for `claude-fable-5-1`, and because it prefix-matches the existing `claude-fable-5` entry the lookup *succeeded* and quietly applied Fable 5's rate. There was no $0 gap and no warning, and input, output and cache writes stayed correct, so the only symptom was a total that ran high. For scale: a heavy week of Claude Code use can log billions of cache-read tokens, so once that traffic moves to 5.1 the 4x error compounds into hundreds or thousands of dollars of phantom cost. Both ids are now priced explicitly, and the same unit test pins Fable 5's original $1 rate so the two generations can't be conflated again.

- **Claude Opus 4.6 requests marked `speed: "fast"` were priced at the 6× fast tier.** Fast mode now covers only Opus 5 and Opus 4.8. On Opus 4.6 a fast request runs at standard speed and is billed at standard rates, so those records now fall back to the normal $5/$25 tier. Opus 4.7 rejects fast requests outright, so no new records can appear for it and its historical tier stays in place for old logs.

- **Every log line was written to two files.** The logging plugin ships with a default file target and the widget was adding its own on top of it instead of replacing it, so each line landed in both `Claude Widget.log` and `widget.log`, and both rotated at 1 MB — about 5 MB of pure duplication across the retained history. Only `widget.log` is written now.

## Notes

- The Claude Sonnet 5 increase to $3/$15 that was scheduled for September 1 was cancelled on August 10, and $2/$10 is now its permanent standard price. The widget was already using $2/$10 so nothing you see changes, but the code and docs still carried instructions to raise it on that date — those have been corrected.
- The fix leaves the old duplicate `Claude Widget*.log` files in place. Delete them yourself if you want the disk space back; on Windows they live in `%LOCALAPPDATA%\com.gnoeynij.claude-widget\logs`.
- The macOS `.dmg` code-signing fix from v2.5.2 still hasn't been confirmed on a real machine. If this one mounts for you that closes the question — if it doesn't, `hdiutil imageinfo` output on the downloaded file would help.
- All costs are *estimates* derived from local JSONL × official pricing (subscribers are not billed per-token).

## 수정

- **Claude Fable 5.1 / Claude Mythos 5.1의 캐시 읽기가 4배 비싸게 계산되던 문제.** 9월 1일 출시된 두 모델은 입력·출력($10/$50)과 캐시 쓰기 단가가 Fable 5와 완전히 같지만, 캐시 읽기만 다른 모든 Claude 모델이 쓰는 0.1x($1)가 아니라 기본 입력가의 0.025x($0.25/MTok)로 과금됩니다 — 이 배수가 모델마다 달라진 첫 사례입니다. 위젯에는 `claude-fable-5-1` 항목이 없었고, 이 ID가 기존 `claude-fable-5` 항목에 prefix 매칭되기 때문에 조회가 *성공하면서* 조용히 Fable 5 단가를 적용했습니다. $0으로 빠지지도 않고 경고도 없으며 입력·출력·캐시 쓰기는 전부 맞아서, 유일한 증상이 "총액이 높게 나오는 것"뿐이었습니다. 규모 참고: Claude Code를 많이 쓰는 한 주면 캐시 읽기가 수십억 토큰에 이를 수 있어, 그 사용량이 5.1로 옮겨가면 4배 오차가 수백~수천 달러의 허수 비용으로 누적됩니다. 이제 두 ID의 단가를 명시적으로 넣었고, 같은 단위 테스트에서 Fable 5의 기존 $1 단가도 함께 고정해 두 세대가 다시 섞이지 않도록 했습니다.

- **Claude Opus 4.6의 `speed: "fast"` 요청이 6배 요율로 계산되던 문제.** 현재 fast 모드는 Opus 5와 Opus 4.8에만 적용됩니다. Opus 4.6에서는 fast 요청이 표준 속도로 실행되고 표준 요율로 과금되므로, 해당 레코드는 이제 일반 $5/$25 단가로 되돌아갑니다. Opus 4.7은 fast 요청 자체를 거부해 새 레코드가 생길 수 없으므로, 과거 로그 계산을 위해 기존 단가를 그대로 둡니다.

- **모든 로그가 두 파일에 중복 기록되던 문제.** 로그 플러그인이 기본 파일 타깃을 이미 갖고 있는데 위젯이 그것을 교체하지 않고 자기 타깃을 *추가*하고 있어서, 모든 줄이 `Claude Widget.log`와 `widget.log` 양쪽에 기록되고 둘 다 1MB마다 로테이션됐습니다 — 보관 중인 로그 기준 약 5MB가 순수 중복이었습니다. 이제 `widget.log`에만 기록됩니다.
