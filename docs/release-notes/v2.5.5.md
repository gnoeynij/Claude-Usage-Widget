# v2.5.5 — Cost totals counted once per request

The widget's cost figures have been far too high — in practice around four times the real amount — because each Claude Code API call appears on disk several times and the widget was adding up every copy. This release counts each call once and rebuilds your stored totals the first time it runs.

## Fixed

- **Costs were counted once per log line instead of once per API call.** Claude Code writes one JSONL line per content block of a response (thinking, text, each tool call), and every one of those lines repeats the full token usage of the call. When you resume a session it also copies earlier messages into the new session file. The widget summed every line, so a response with four blocks was charged four times, plus again for every resumed copy. Every dollar figure was affected — today, yesterday, this week, this month, 5-hour blocks, the per-model breakdown, the lifetime total and the milestone toasts. Usage limit percentages come straight from Anthropic and were never affected. Records are now collapsed by message id + request id across all log files, keeping the most complete copy.

- **Yesterday's cost kept climbing after midnight.** Resuming yesterday's session copied its messages, with their original timestamps, into today's session file, and the widget added them to yesterday's total again. With duplicates collapsed, past days now stay put.

- **Cost tracking stopped while the usage API was failing.** If sign-in expired or the network was down, local cost aggregation was skipped along with the usage fetch. Cost comes from your local logs, so it now keeps updating regardless.

- **A rare double-count of the lifetime total** when a sync and a switch to Detail mode overlapped.

## Notes

- **Your totals will drop the first time v2.5.5 runs.** Stored history and the lifetime total were built with the old calculation and are only ever merged upward, so the widget recalculates them once from the logs still on disk. Days whose logs Claude Code has already cleaned up can't be recalculated and keep their previous values.
- If you combine several devices through a shared folder, each device corrects its own share when it updates to v2.5.5 — until then the combined total still includes that device's old figures.
- Claude Sonnet 5.5 is now priced explicitly (same rates as Sonnet 5).
- The macOS `.dmg` code-signing fix from v2.5.2 still hasn't been confirmed on a real machine. If this one mounts for you that closes the question — if it doesn't, `hdiutil imageinfo` output on the downloaded file would help.
- All costs are *estimates* derived from local JSONL × official pricing (subscribers are not billed per-token).

위젯의 비용 표시가 실제보다 크게 — 실사용 기준 약 4배 — 높았습니다. Claude Code의 API 호출 하나가 디스크에 여러 번 기록되는데 위젯이 모든 사본을 더했기 때문입니다. 이번 릴리즈부터 호출당 한 번만 세고, 처음 실행될 때 저장된 합계를 다시 계산합니다.

## 수정

- **비용을 API 호출이 아니라 로그 줄마다 세던 문제.** Claude Code는 응답의 내용 블록(생각·텍스트·도구 호출 각각)마다 JSONL 한 줄을 쓰고, 모든 줄에 그 호출의 토큰 사용량 전체를 반복해 기록합니다. 세션을 이어하면 이전 메시지를 새 세션 파일에 복사하기도 합니다. 위젯은 모든 줄을 더해서 블록이 넷인 응답을 네 번 과금했고, 이어하기 사본마다 또 더했습니다. 오늘·어제·이번 주·이번 달, 5시간 블록, 모델별 비용, 누적 합계, 마일스톤 알림까지 모든 금액이 영향을 받았습니다. 한도 %는 Anthropic에서 직접 받아오므로 영향이 없었습니다. 이제 모든 로그 파일에 걸쳐 메시지 ID + 요청 ID로 사본을 합치고, 가장 완전한 사본을 남깁니다.

- **어제 비용이 자정 이후에도 계속 오르던 문제.** 어제 세션을 이어하면 그 메시지가 원래 타임스탬프 그대로 오늘 세션 파일에 복사되고, 위젯이 그걸 어제 합계에 다시 더했습니다. 사본을 합치면서 지난 날짜는 더 이상 변하지 않습니다.

- **사용량 API가 실패하는 동안 비용 집계도 멈추던 문제.** 로그인 만료나 네트워크 장애로 사용량 조회가 실패하면 로컬 비용 집계까지 건너뛰었습니다. 비용은 로컬 로그에서 계산하므로 이제 그와 무관하게 계속 갱신됩니다.

- **드물게 누적 합계가 이중으로 더해지던 문제** — 동기화와 Detail 모드 전환이 겹칠 때.

## 비고

- **v2.5.5를 처음 실행하면 합계가 내려갑니다.** 저장된 이력과 누적 합계는 옛 계산으로 만들어졌고 위로만 병합되는 구조라, 디스크에 남아 있는 로그로 한 번 다시 계산합니다. Claude Code가 이미 정리한 날짜의 로그는 다시 계산할 수 없어 기존 값이 유지됩니다.
- 공유 폴더로 여러 기기를 합산하고 있다면, 각 기기가 v2.5.5로 업데이트될 때 자기 몫을 보정합니다 — 그 전까지 합산 총액에는 그 기기의 옛 값이 들어 있습니다.
- Claude Sonnet 5.5 단가를 명시적으로 추가했습니다(Sonnet 5와 동일).
- v2.5.2의 macOS `.dmg` 코드 서명 수정은 아직 실기기에서 확인되지 않았습니다. 이번 dmg가 정상적으로 마운트되면 그것으로 확정되고, 여전히 안 되면 다운로드한 파일의 `hdiutil imageinfo` 출력을 알려주시면 도움이 됩니다.
- 모든 비용은 로컬 JSONL × 공식 단가표 기반 *추정치*입니다(구독 사용자는 실제 토큰당 과금 없음).
