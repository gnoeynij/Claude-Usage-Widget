# v2.5.2 — macOS installer fix, take two

v2.5.1's fix addressed a real but secondary issue. This release fixes the actual cause: the app was never code-signed, and Apple Silicon requires a signature for anything downloaded from the internet.

## Fixed

- **macOS `.dmg` still showed "is damaged" after v2.5.1.** Diagnosis this time was conclusive: `hdiutil imageinfo` run directly on the downloaded file confirmed the disk image itself is byte-perfect (valid structure, matching checksums on every partition) — so it was never actually corrupted. The real problem is that `tauri.conf.json` never configured a signing identity, so the `.app` inside shipped with no bundle-level code signature at all. Apple Silicon refuses to run unsigned executables downloaded from the internet, and Gatekeeper's message for that case is the same generic "is damaged" dialog rather than a clearer signing warning — which is what sent the last two releases chasing the wrong cause. The app now gets ad-hoc self-signed at build time (free, no Apple Developer account needed). This should make the standard first-launch flow apply as documented: right-click → Open, or `xattr -d com.apple.quarantine`.

## Notes

- v2.5.1's CI-pipeline fix (skipping an unreliable Finder-styling step) was a legitimate improvement and stays in place — it just wasn't the cause of this particular symptom.
- This is the second real-device check in as many releases — if `.dmg` still won't mount, please report it with `hdiutil imageinfo` output on the downloaded file.
- All costs are *estimates* derived from local JSONL × official pricing (subscribers are not billed per-token).

## Download

### Windows
- `Claude Widget_2.5.2_x64-setup.exe` — NSIS installer (recommended)
- v2.0.x and later: Settings → "Check for updates" for automatic delivery

### macOS (Apple Silicon)
- `Claude Widget_2.5.2_aarch64.dmg` — DMG installer
- First-launch Gatekeeper bypass: right-click → Open, or `xattr -d com.apple.quarantine "/Applications/Claude Widget.app"`

## System requirements

- Windows 10/11 (Win11 recommended — Mica vibrancy)
- macOS 11 Big Sur or later (Apple Silicon)
- WebView2 Runtime (auto-installed by the Win10 installer)

- **v2.5.1 이후에도 macOS `.dmg`가 여전히 "손상됨"으로 뜨던 문제.** 이번엔 진단이 확정적이었습니다 — 다운로드한 파일에 `hdiutil imageinfo`를 직접 돌려보니 디스크 이미지 자체는 완벽한 구조(모든 파티션 체크섬 일치)로 확인돼, 애초에 손상된 적이 없었습니다. 진짜 문제는 `tauri.conf.json`에 서명 identity가 한 번도 설정된 적이 없어서 내부 `.app`이 번들 레벨 코드 서명 자체가 아예 없이 배포되고 있었던 것입니다. Apple Silicon은 인터넷에서 받은 서명 없는 실행 파일 실행을 거부하는데, 이 경우 Gatekeeper가 더 명확한 서명 경고 대신 똑같은 범용 "손상됨" 다이얼로그를 띄우는 바람에 지난 두 릴리즈가 엉뚱한 원인을 쫓게 됐습니다. 이제 빌드 시점에 무료 ad-hoc 자가서명이 적용됩니다(Apple Developer 계정 불필요). 이제부터는 문서화된 표준 첫 실행 절차(우클릭 → 열기, 또는 `xattr -d com.apple.quarantine`)가 정상적으로 적용될 것입니다.
