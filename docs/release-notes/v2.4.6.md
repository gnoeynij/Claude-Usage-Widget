# v2.4.6 — Token expiry heals itself

The widget now recovers from an expired Claude Code token on its own — no more opening a terminal just to run `claude` once. When sign-in is actually needed, a button takes you straight there.

## What's new

- **Expired token? The widget fixes it.** When the OAuth token expires, the widget quietly runs a minimal Claude Code call in the background, which makes the CLI refresh the token — then re-syncs. Measured end-to-end: expired to recovered in under a minute, zero interaction. The call is capped at **one CLI run per expiry episode** (plus a 10-minute floor that survives restarts), so it can never loop or run up costs (~$0.015 per episode, roughly one small haiku call).
- **"Open login" button.** When credentials are missing entirely (signed out), the error banner now has a button that opens a terminal running `claude auth login` — the browser sign-in flow starts by itself, and the widget picks the new token up automatically once you're done. If the terminal can't be opened (CLI not found, macOS automation permission), the widget says so with a toast instead of failing silently.

## Changed

- **Clearer error hints.** The token-expired banner now says the widget is trying to refresh automatically (and what to do if it persists); the no-credentials hint names the concrete command in every mode.
- **Guide/README accuracy.** The projection explanation now matches v2.4.4 behavior: the session estimate blends in a faster recent pace, while weekly uses the week-to-date average only. README change log backfilled for v2.4.2 – v2.4.5.

## Notes

- The refresh trigger runs `claude` with `--no-session-persistence` from a neutral directory, so it never pollutes the widget's own cost statistics. Like any API call it does consume a tiny slice of the server-side usage window.
- All costs are *estimates* derived from local JSONL × official pricing (subscribers are not billed per-token).
- macOS: the login-terminal path is implemented but not yet field-verified on real hardware.

## 새 기능

- **토큰이 만료되면 위젯이 알아서 고칩니다.** OAuth 토큰이 만료되면 위젯이 백그라운드에서 최소한의 Claude Code 호출을 조용히 실행해 CLI가 토큰을 갱신하게 만든 뒤 재동기화합니다. 실측 기준 만료→복구까지 1분 이내, 개입 0회. 호출은 **만료 에피소드당 CLI 실행 1회**(+ 재시작에도 유지되는 10분 하한)로 고정되어 반복 실행·과금 누적이 구조적으로 불가능합니다 (에피소드당 ~$0.015, 작은 haiku 호출 1회 수준).
- **"로그인 열기" 버튼.** 자격증명이 아예 없는(로그아웃) 상태에서는 에러 배너의 버튼이 `claude auth login`을 실행하는 터미널을 열어줍니다 — 브라우저 로그인이 자동으로 시작되고, 완료하면 위젯이 새 토큰을 스스로 감지합니다. 터미널을 못 여는 경우(CLI 미발견, macOS 자동화 권한)엔 조용히 실패하는 대신 토스트로 알려줍니다.

## 변경

- **더 명확한 에러 안내.** 토큰 만료 배너가 자동 갱신 시도 중임을(지속 시 할 일과 함께) 알려주고, 자격증명 없음 안내는 모든 모드에서 구체적인 명령어를 직접 안내합니다.
- **가이드/README 정확성.** 투영 설명이 v2.4.4 동작과 일치하도록 정정 — 세션은 최근 페이스를 반영하고 주간은 누적 평균만 사용합니다. README 체인지 로그에 v2.4.2~v2.4.5 누락분을 백필했습니다.

## 비고

- 갱신 트리거는 중립 디렉토리에서 `--no-session-persistence`로 실행되어 위젯의 비용 통계를 오염시키지 않습니다. 다만 일반 API 호출처럼 서버측 사용량 창은 아주 조금 소모합니다.
- 모든 비용은 로컬 JSONL × 공식 단가표 기반 *추정치*입니다(구독 사용자는 실제 토큰당 과금 없음).
- macOS: 로그인 터미널 경로는 구현되어 있으나 실기기 검증 전입니다.
